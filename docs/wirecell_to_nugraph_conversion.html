Wire-Cell → NuGraph conversion (pywcml)

How Wire-Cell ML blobs, measurements (CTPC), and point-point edges become NuGraph hit / sp nodes and the edges between them.

Source: pywcml/{io.py, geometry.py, config.py, converter.py} — WCMLConverter._build_graph() is the heart of it. The result is one NuGraphData heterogeneous graph per event, saved into an HDF5 dataset that H5DataModule feeds to NuGraph3 / NuGraph4.

Naming gotcha. In NuGraph a hit node is not a single Wire-Cell hit — it is a cluster of CTPC measurements on one wire plane. The 3D sp node is the blob. Keep this mapping in mind throughout.

2 · Input: the NPZ arrays (io.py)

load_npz() reads one rec-lab-*.npz into a WCMLArrays bundle:

ArrayShapeColumns / meaning
blobs(N_blob, ·)[0]=charge, [1]=n_corners, [2:2+3·n_corners]=corner xyz…
points(N_pt, ≥6)3D points; [:,4]=blob_id, [:,5]=reco_cluster_id
ctpc_*(N_ctpc, 4)per plane: [0]=x(drift), [1]=pitch/wire, [2]=charge, [3]=charge_err
is_nu(N_pt,)per-point truth: 1=ν (signal), 0=cosmic, -2=unmatched/ghost
ppedges(N_e, ≥2)[:,0],[:,1] = head/tail point indices
edge_index(2, E)truth supervision edges, point indices
vtx_dist/dx/dy/dz(N_pt,)optional per-point neutrino-vertex geometry (cm)

Everything downstream is an aggregation of points / CTPC up to the blob (sp) or stripe (hit) level.

3 · sp nodes — one per blob

Built in _build_graph() from _extract_blobs():

blobs[i] = [charge_i, n_corners_i, x0,y0,z0, x1,y1,z1, …]
       ──► corners_i  = reshape(n_corners_i, 3)
           centroid_i = mean(corners_i, axis=0)          # 3D position (mm)
sp attributeSource
sp.pos (N,3)blob centroid (mean of corners)
sp.features (N,6)[charge, reco_cluster_id, vtx_dist, vtx_dx, vtx_dy, vtx_dz]
sp.y_semantic (N,)per-blob class: 0=nu, 1=cosmic, -1=ghost (see §6)
sp.y_instance (N,)truth_blob_tid if present, else reco-cluster id; -1 on ghosts
  • charge = blobs[:,0].
  • reco_cluster_id = per-blob mode of points[:,5] (_reco_cluster_by_blob).
  • vtx_* = mean over the blob's hits of the per-point vertex quantities, cm→mm (only trusted when nu_vtx_found); zeroed / -1 on ghost blobs so truth can't leak.

4 · hit nodes — CTPC stripes per plane (_build_plane)

Each plane (u, v, y) is processed independently. A hit node is a contiguous run of CTPC measurements at one drift position:

flowchart TD A["ctpc_plane rows
[x, pitch, charge, charge_err]"] --> B["sort by x (drift)"] B --> C["group rows with
|Δx| ≤ x_tolerance (5 mm)"] C --> D["within a group sort by pitch,
split where gap > pitch_gap_tolerance (6 mm)"] D --> E["each contiguous stripe = one hit node"] E --> F["charge-weighted centroid (wx, wy)
features: total_charge, mean_charge_err,
nhits, pitch_min, pitch_max"]
hit attributeSource
pos (M,2)charge-weighted (wx, wy) of the stripe's CTPC rows
x (features)[total_charge, mean_charge_err, nhits, pitch_min, pitch_max] + 4 vertex + 6 sidecar = 15 cols
y_semantic (M,)propagated from linked blobs (positive wins)
y_instance (M,)mode of linked blob truth-instance ids

Sidecar/vertex columns are zeros unless explicitly enabled (enable_sidecar_features, etc.). The model only consumes a leading slice of these (Transform trims hit.x to in_features).

5 · Edges

5.1 (hit, plane, hit) — intra-plane Delaunay

geometry.triangulation_edges(pos_array) runs a 2D Delaunay triangulation over the plane's hit positions and keeps the unique undirected triangle edges (falls back to a complete graph for degenerate/tiny sets). → graph[plane,"plane",plane].edge_index.

5.2 (hit, nexus, sp) — hit ↔ blob association

For every blob, its 3D corners are projected into the plane coordinate via project_corners(corners, angle) = cos θ·z − sin θ·y (θ from PlaneSpec). A hit node links to that blob when both hold:

  • drift match: |hit.x − blob_centroid.x| ≤ x_tolerance, and
  • pitch overlap: the projected corner range intersects the hit's [pitch_min, pitch_max] (± projection_tolerance).

Each link (hit_node, blob) is recorded; the blob's semantic/instance labels are also pushed onto that hit node here. → graph[plane,"nexus","sp"].edge_index = to_sp.T.

5.3 (sp, nexus, sp) — blob message-passing graph

ppedges are point↔point; _ppedges_to_blobedges maps each endpoint to its blob_id (points[:,4]), drops self-loops, and keeps unique undirected blob pairs. Edges touching a ghost blob are pruned. → graph["sp","nexus","sp"].edge_index.

5.4 (sp, supervision, sp) — truth "same-instance?" edges

The truth edge_index (point indices) is mapped to blob pairs and labelled by _label_blob_edges:

labelable = 1  ⇔  both endpoints have a valid truth instance id (tid ≥ 0) AND neither is ghost
edge_y    = 1  ⇔  labelable AND both endpoints share the same tid

Stored on the sp store as edge_label_index, edge_y, edge_labelable. (If empty, a dummy unlabelable 0→0 self-edge is injected so HDF5 doesn't collapse the tensor.) This is exactly the supervision signal NuGraph4's edge / embedding losses consume.

6 · Semantic & instance labels

is_nu (per point)           blob aggregation                    encode
──────────────────          ────────────────────────────       ────────────────
 1  (ν / signal)    ─┐      any ν point in blob → "nu"          "nu"    →  0
 0  (cosmic)         ├──►   else if known points → "cosmic"     "cosmic"→  1
-2  (unmatched)     ─┘      all points -2        → ghost         ghost  → -1  (ignored by loss)
  • _label_blobs computes the per-blob class and frac_nu_hits (ν purity).
  • _encode_semantic_labels maps to the model's convention {nu:0, cosmic:1, ghost:-1}.
  • Ghost hygiene is enforced twice: ghost sp get vtx_* wiped, y_instance=-1, and are pruned from both MP and supervision edges — so unmatched blobs never leak truth or carry loss.

Optional label refinements (off by default)

  • enable_vertex_semantic_fix: flip false-negative blobs to ν if within 50 mm of the vertex and they actually contain ν hits.
  • enable_semantic_mp_propagation_fix: BFS-spread ν labels from confident near-vertex seeds along the MP graph (_semantic_propagate_on_mp), bounded by hops / edge length / vtx distance; only ever flips cosmic → nu, never touches ghosts.

7 · From per-plane stores to the unified hit node

The converter writes separate u/v/y stores. At load time the dataset reshapes them into what the model expects:

  • Transform (models/nugraph3/transform.py): concatenates the three plane stores into a single hit node type, offsets and merges their edges into (hit, delaunay-planar, hit) and (hit, nexus, sp), appends a plane-id column, copies y_instance → pid, builds (hit, in, evt), and finally prepends pos to hit.x and trims it to in_features.
  • NuGraphDataset.get (data/dataset.py): promotes the sp.edge_label_index (+edge_y, edge_labelable) into a real (sp, supervision, sp) edge store, and re-asserts the ghost-masking invariant y_instance[y_semantic==-1] = -1.

After these two steps the graph matches the node/edge types documented in nugraph4_architecture.html.
