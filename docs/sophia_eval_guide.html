01 What is being measured

Two numbers per event, both about the neutrino class.

neutrino efficiency = correct-nu / true-nu

Of everything that is neutrino, the fraction NuGraph tagged as neutrino. This is recall — it answers “did we find the neutrino?”

neutrino purity = correct-nu / predicted-nu

Of everything NuGraph called neutrino, the fraction that really is. This is precision — it answers “is what we found actually neutrino?”

The unit is a blob, not a hit

NuGraph's semantic head predicts per plane-hit, emitting a two-class softmax [p(nu), p(cosmic)]. A blob (3D spacepoint) has no prediction of its own — it inherits one by averaging its hits' p(nu) along the nexus edges that connect hits to blobs:

p(nu)_blob = mean( p(nu)_hit  for every hit wired to that blob )
predicted nu  <=>  p(nu)_blob >= 0.5

The threshold is on p(nu). Because it is a two-class problem, 0.5 simply means “neutrino is the more likely class.” Sweeping this threshold is exactly what generates the purity–efficiency curve.

Why blobs

Blob-space is both the more faithful measure and what the Bee event display shows. Blobs carry a real truth label; scoring individual hits requires propagating blob truth back down the nexus edge (first-edge-wins), which is noisy. Averaging several hits also smooths per-hit fluctuation.

Reported metrics are unweighted blob counts — not charge-weighted. A charge-weighted variant exists separately.

The checkpoint is the best-f1 epoch, selected on semantic/f1-macro-val. In this training run best-f1, best-instance-f1 and best-joint-f1 are byte-identical.

Compute note

These evaluation scripts load the checkpoint with map_location="cpu" and run on CPU. The GPU is not required — the single-gpu queue is used for consistency with the rest of the pipeline and because it schedules quickly. Runtime is dominated by model construction (~90 s); the 20-graph forward pass itself is seconds.

Run this through the scheduler, not on a Sophia login node.

03 Quick start

One submission reproduces both the metrics table and the event display.

Submit

# from anywhere on Sophia
qsub /lus/eagle/projects/neutrinoGPU/snehadri/sbnd/nugraph_perevent_eval.pbs

# watch it
qstat -u $USER
tail -f /lus/eagle/projects/neutrinoGPU/snehadri/sbnd/nugraph_perevent_eval.pbs.log

nugraph_perevent_eval.pbs — job header

#PBS -N ng_perevent
#PBS -A neutrinogpu::wirecell
#PBS -q single-gpu
#PBS -l select=1:ncpus=16:ngpus=1
#PBS -l filesystems=eagle:home
#PBS -l walltime=01:00:00
#PBS -j oe

Total wall time is a few minutes; the one-hour request is headroom. The job runs the three stages in §04 in order and is idempotent — stage 1 is skipped if the event file already exists.

Interactive alternative

To iterate on a single stage, take an interactive node rather than running on the login node:

qsub -I -A neutrinogpu::wirecell -q single-gpu \
     -l select=1:ncpus=16:ngpus=1 -l filesystems=eagle:home \
     -l walltime=01:00:00

# then, on the compute node
SB=/lus/eagle/projects/neutrinoGPU/snehadri/sbnd
PY=/lus/eagle/projects/neutrinoGPU/abhat/conda/envs/nugraph-a/bin/python
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
cd $SB

04 The three stages

Select events → score them → render them. Each stage is a standalone script taking absolute paths, so it can be re-run on its own.

Stage 1 — Select 10 complete, balanced events

select_events.py → data/abhat_events.h5

$PY $SB/select_events.py

The source H5 stores one graph per APA (drift volume). SBND has two, so one physics event is two graphs. A neutrino occupies only one drift volume, which is why a lone APA graph can contain no neutrino at all. The selection therefore works at event level:

  • Parse every test-split graph name into (file, entry, apa) and keep only events whose both APAs are in the test split — 14,295 of 52,893 graphs qualify. (The split is per-graph, so an event's halves often straddle train and test.)
  • Sample 220 of those events evenly across the list.
  • Score neutrino content from blob truth (sp/y_semantic, class 0 = nu), pooling both APAs.
  • Require a genuine mix: >200 blobs total, and at least 60 neutrino and 60 cosmic blobs.
  • Rank by |nu_frac − 0.5| and keep the 10 closest to balanced.

Output is written with each event's apa0 immediately followed by its apa1. Downstream scripts rely on this ordering to pool every two consecutive graphs into one event.

Stage 2 — Per-event semantic metrics

perevent_semantic_blob.py → results/perevent_semantic_blob.csv

$PY $SB/perevent_semantic_blob.py \
    $SB/data/abhat_events.h5 \
    "$CKPT" \
    $SB/results/perevent_semantic_blob.csv \
    0.5          # threshold on p(nu)

For each labelled blob it averages hit p(nu) through the nexus edge, thresholds at 0.5, pools both APAs, and emits one row per event. CSV columns:

event,n_blobs,n_nu,nu_frac,efficiency,purity

Events are zero-indexed (0–9), matching the Bee display.

Stage 3 — Bee event display

bee_nugraph_events.py → results/bee_events10/bee-nugraph.zip

$PY $SB/bee_nugraph_events.py \
    $SB/data/abhat_events.h5 \
    "$CKPT" \
    $SB/results/bee_events10 \
    0.5

Writes one Bee folder per physics event (both APAs merged, so 10 folders, not 20). Each event carries four point-sets, all viewed through “Show Cluster” so no color-scale adjustment is needed:

Setcluster_id encodes
truth-semantic0 = cosmic, 1 = nu (truth)
nugraph-semantic0 = cosmic, 1 = nu (predicted)
truth-instancetrue instance id
nugraph-instancepredicted instance id (edge head + union-find)
Expected asymmetry

The nugraph-* sets contain more points than the truth-* sets. Truth sets draw only blobs carrying a label (y_semantic ≥ 0); NuGraph scores every reconstructed spacepoint, including Wire-Cell ghost blobs that truth-matching could not tie to any energy deposit. This is expected, not a bug.

Download the zip and upload it to Bee:

scp sophia.alcf.anl.gov:/lus/eagle/projects/neutrinoGPU/snehadri/sbnd/results/bee_events10/bee-nugraph.zip .

06 How to read these numbers

Not a representative sample

These ten events were deliberately selected for class balance (30–68% neutrino blobs). Typical events in this dataset are far more cosmic-dominated — roughly 8% neutrino pooled. Purity in particular is easier at high neutrino fraction, because a no-skill classifier's purity equals the neutrino prior. These numbers characterize behavior on neutrino-rich events, not average detector conditions.

  • Threshold is a free parameter. 0.5 is the default, not an optimum. The purity–efficiency curve (pr_curve.py) traces the full trade-off.
  • Unweighted. Blob counts, not charge-weighted; large and small blobs count equally.
  • Held-out data. Events come only from the test split of the training dataset.
  • Instance clustering is truth-gated. The predicted-instance set derives from the edge head and requires labelable edges, so it degrades to one-cluster-per-blob on unlabeled real data. Semantic results are unaffected.
