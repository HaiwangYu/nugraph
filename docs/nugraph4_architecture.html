NuGraph4 — Architecture, Loss Backprop & Inference

Heterogeneous GNN for LArTPC hit classification & particle-instance clustering. Branch feature/nugraph4-beta. NuGraph4 subclasses NuGraph3 and adds three instance-aware losses.

hit node (2D wire-plane hit) sp node (spacepoint / "nexus") evt node (interaction) Encoder Core (×10 message passing)

1 · The heterogeneous graph

Each event is one heterogeneous graph with three node types and several typed edges. All learned representations live on these nodes; every loss is just a different read-out head over the same shared trunk (Encoder → Core).

2 · Forward pass — the shared trunk

NuGraph3.forward runs the encoder once, then the core num_iters = 10 times, then every decoder head. NuGraph4.forward calls super().forward() first, then computes the extra instance losses on the resulting embeddings.

Dimensions and loss weights below follow the production launch config notebooks/nugraph_polaris_prod.pbs in abhat's working dir: in_features=4, hit_features=256, nexus_features=64, interaction_features=32, num_iters=10; use_sp_features=True, use_vtx_features=False (only sp.features cols 0–1 consumed; vertex cols dropped); λ_embed=0.3, λ_edge=0.01, λ_coh=0, edge_pos_weight=0.15.

The Encoder + Core is one shared trunk. Every loss below is a head reading the trunk's output embeddings. Because they share the trunk, gradients from all losses sum into the same encoder/core weights — this is multi-task learning.

Active in the production config (nugraph_polaris_prod.pbs): only Lsemantic, Lembed (λ=0.3) and Ledge (λ=0.01). Lfilter is off because the --filter-head flag isn't passed (so FilterDecoder is never built), and Lcoh is off because λ_coh=0 (the coherence block is skipped entirely). Effective objective: Ltotal = Lsemantic + 0.3·Lembed + 0.01·Ledge.

Lembed in detail (the instance-aware core)

Per event, take the SP embeddings z = sp.x, L2-normalise, build the full pairwise distance matrix, and split pairs by truth instance id:

loss_pos = mean( d(z_i, z_j)² )           for pairs with same pid   → pull together
loss_neg = mean( relu(margin − d(z_i,z_j))² )  for pairs with diff pid → push apart (margin=0.5)
L_embed  = mean over events ( loss_pos + loss_neg )

It has no learnable parameters of its own — it only sculpts the geometry of sp.x so same-particle spacepoints cluster and different-particle ones separate by a margin. That is the signal NuGraph3 lacked for instance segmentation.

4 · How gradients back-propagate

Every loss is differentiated w.r.t. its inputs and the chain rule carries gradients back into the shared trunk. Solid arrows = differentiable path; the loss weights act as gradient scales.

Path of each gradient

  • Lsemantic → SemanticDecoder MLP weights (+temp) → hit.x → Core → Encoder. Ghost hits (y=-1) are masked, contribute zero gradient.
  • Lfilter → (off in prod — --filter-head not set, so FilterDecoder is never built; no gradient path). When enabled it would go Filter Linear (+temp) → hit.x → Core → Encoder.
  • Lembed → directly into sp.x (no head params) → Core (nexus blocks) → Encoder. Scaled by the warm-up/ramp schedule × 0.3.
  • Ledge → edge_mlp_sp weights and through the endpoint embeddings sp.x → Core → Encoder. Active at λ=0.01 (weak but non-zero, so the edge head is trained); logits also stashed for eval.
  • Lcoh → (off in prod — λ_coh=0, the coherence block is skipped and nothing is computed). When enabled it flows through hit.x_semantic (semantic probs) → SemanticDecoder → trunk. Note cluster construction is non-differentiable (hard p_same≥0.7 threshold + union-find): the cluster membership mask carries no gradient; only the variance-of-probs term inside each fixed cluster would.
Warm-up / ramp-up schedule. λ_embed and λ_edge are not constant during training: epochs 0–9 weight=0 (semantic-only), epochs 10–19 linearly ramp 0→λ, epoch 20+ full λ. So early on, only the semantic gradients shape the trunk; the contrastive / edge signals are phased in once the embeddings are meaningful.
Implementation note. NuGraph4.__init__ also builds embedding_decoder, semantic_head and a hit-level edge_mlp, but the active forward path computes L_embed/L_edge directly on sp.x via _instance_embedding_loss and edge_mlp_sp. Those extra modules are defined but not on the live loss path in this beta.

5 · Inference time

At inference (predict_step → self(batch) with stage=None) no loss is added to anything and nothing is back-propagated. The same trunk runs; decoders write predictions onto the graph instead of optimising.

What you get out

  • Semantic class per hit: argmax(hit.x_semantic) over the 5 classes (MIP/HIP/shower/michel/diffuse). This is the always-available primary output.
  • Filter score per hit — not produced in prod: the filter head isn't enabled, so there's no signal/noise output. (Background rejection instead falls out of the semantic classes.)
  • Particle instances (NuGraph4's purpose): the edge_mlp_sp scores every supervision SP–SP edge, sigmoid → p_same; edges with p_same ≥ edge_thr (default 0.7) are kept and run through union-find to form connected components = clustered spacepoints = reconstructed particles (clusters_from_edges in eval_semantic.py).
Checkpoint note for clustering. Instance clustering at inference relies on edge_logits, which are only meaningful if the checkpoint was trained with λ_edge > 0. The production config (nugraph_polaris_prod.pbs) uses λ_edge=0.01 > 0, so the edge head is trained and eval_semantic.py can run the edge-based clustering. The weight is small, though, so the edge head is only weakly supervised — much of the instance signal still comes from the contrastive-shaped sp.x embeddings (L_embed, λ=0.3), which can also be clustered directly by embedding distance. (A checkpoint trained with λ_edge=0 — e.g. nugraph_ofi.pbs — would leave the edge head untrained and skip clustering.)
Training vs inference — the key difference. The trunk and decoder heads are identical; only what happens to their outputs differs.
· Training: heads produce predictions → losses computed against truth → summed → loss.backward() updates trunk + heads.
· Inference: heads produce predictions → written onto the graph → consumed by argmax / thresholding / union-find. No truth, no loss, no gradient.
